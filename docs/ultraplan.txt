# Stacking, Data, and Production Wiring — Revised Plan

## Context

`docs/STACKING_AND_DATA_FIX_PLAN.md` documents Phases 0-7: dedup recovery (700 → 8,724 triplets), RRF eval harness, v2/v3 training. RRF stacking landed +12.8% NDCG. **Three structural problems remain, plus several inaccuracies in the original Phase G plan that exploration has corrected.**

### What exploration confirmed
- Production reranker is dead code: `from lib.reranker import rerank_results` at `src/lib/tools.py:27` has no callers; `_handle_search_academic` (line 720) returns OpenAlex docs straight to `format_openalex_results` with no rerank step.
- v3+RRF lost 0.8% vs v2+RRF; postulated cause (`_make_text` enrichment overlapping BM25) is untested.
- Strategy 3 caps confirmed: `max_total=4000` (line 656), `[:4]` subjects (line 659), `[:2]` docs (line 681).
- Dedup truncated to 200 chars (`generate_sfu_training_data.py:870`), unseeded query gen (line 467), non-stable `hash()` for per-(provider,subject) RNG (line 673).

### What the original draft got wrong (corrected here)
- **`SFU_FEATURE_RRF_ENABLED` already exists.** `src/lib/config.py:160-166` already loads `rrf_enabled` and `rerank_enabled` from `SFU_FEATURE_*` env vars. The fix is *consuming* the flag at the call site, not adding it.
- **MNRL is already the loss.** `train_embedding_model.py:364` is `MultipleNegativesRankingLoss(model)`, not `TripletLoss`. The Phase L "switch loss" task is a no-op.
- **`--base-model` is already a CLI flag.** `train_embedding_model.py:697`. Switching to BGE-small is one CLI arg, not a code change.
- **The reranker is Primo-shaped, but production returns OpenAlex flat docs.** `reranker.py` reads `doc["pnx"]["display"][...]`; OpenAlex docs are flat `title`, `authors`, `topics`, `cited_by_count`. There is no Primo path in `tools.py` anymore. Wiring requires a normalization layer or an OpenAlex-aware path.

### User's added requirement (this revision)
Provide training-data alternatives to OpenAlex due to API token limitations: local sources and synthetic generation. Phase I-bis is added to cover this.

### Intended outcome
1. Production actually runs RRF (current users get raw OpenAlex order).
2. The v3 regression is mechanistically explained.
3. Provider/subject coverage is genuinely uniform.
4. The data pipeline can produce useful triplets even when OpenAlex is rate-limited or exhausted.

## Phase G — Production wiring (no API; ship first)

### G.1 — Normalize the reranker on a doc shape that exists in production
`reranker.py` reads `doc["pnx"]["display"]["title"]`; production `_handle_search_academic` returns OpenAlex flat dicts. Two options:

- **G.1a (chosen): add a thin `_normalize_for_rerank(doc)` adapter in `reranker.py`** that returns a shape-stable view: `{"title", "abstract", "year", "type", "doi", "authors", "has_fulltext"}`. Drive `_score_title_relevance`, `_score_recency`, `_score_fulltext`, `_score_type_match`, `_score_completeness` off this view rather than off `pnx`. Adapter detects shape: if `doc.get("pnx")` exists, read pnx; else treat as OpenAlex flat (`title`, `abstract`, `publication_year`/`date`, `cited_by_count`, etc.).
- Rejected: keeping two parallel score paths — duplicates code and the Primo path is currently dead.

This refactor is a few-dozen-line, fully-testable change and resolves the "production gets nothing" problem.

### G.2 — Consume the existing env flags at the call site
- `_get_features()` in `tools.py:47` already returns `rrf_enabled` and `rerank_enabled` (loaded from `SFU_FEATURE_*` in `config.py:162-166`). They just have no consumer.
- Add a `_maybe_rerank(docs, query, limit)` helper near the top of `tools.py`:
  - Short-circuit to `docs[:limit]` if `_get_features().get("rerank_enabled")` is False.
  - Else call `rerank_results(docs, query, limit, use_embedding=True, use_rrf=_get_features().get("rrf_enabled"))`.
  - Wrap in try/except that logs and falls back to `docs[:limit]` (never break search on reranker error).
- Call it inside `_handle_search_academic` (line ~745) on `data["results"]` before `format_openalex_results(data, query)`. Mirror in `_handle_search_by_topic` (line 804) and any future paper-returning handler. Skip metadata-only handlers (`_handle_browse_sfu_databases`, hours, location).

### G.3 — Tests
- Extend `src/tests/test_reranker.py`:
  - New tests passing OpenAlex-flat docs through `rerank_results`. The existing 13 tests use `pnx` and must still pass.
  - Test that `_normalize_for_rerank` correctly extracts both shapes.
- New `src/tests/test_tools_rerank.py` (or extend existing tests):
  - `monkeypatch` `rerank_results`, call `_handle_search_academic`, assert reranker was invoked when `rerank_enabled=True`, skipped when False, and `use_rrf` propagates from the feature flag.

### G.4 — Observability
Add one log line at the end of `rerank_results`: `logger.info("rerank: rrf=%s embed=%s docs=%d -> %d", use_rrf, bool(semantic_scores), len(docs), limit)`. Bump version string in `config.py` so the deploy is identifiable.

### G.5 — Roll-out
1. Deploy with both flags **off** (current default) — confirms the wiring change is invisible.
2. Flip `SFU_FEATURE_RERANK_ENABLED=true` (default in `config.py:155` is already True; verify env doesn't override).
3. After 24h soak, flip `SFU_FEATURE_RRF_ENABLED=true`.

```ascii
─────────────                     ─────────────

       → format_openalex_results          → _maybe_rerank ──► rerank_results
                                                    │           │
```

## Phase H — Isolate the v3 regression

Hypothesis from the existing doc: `_make_text` enrichment (`Venue | Topics | Keywords` appended at `generate_sfu_training_data.py:322-345`) makes v3's embeddings less orthogonal to BM25, suppressing RRF gain. Testable in ~2 GPU-hours with zero API spend.

### H.1 — Verify raw triplets are re-renderable
The v3 enrichment lives in the *rendered text* stored in `data/sfu_training_triplets.jsonl`, not in the raw OpenAlex work. Before any ablation work, **read the raw JSONL and confirm** the rendered text alone is what's stored vs. whether the work dict is preserved. If only rendered text is stored, the raw schema must change to keep the original work fields so re-rendering can happen during `--reclean-only`. Without this fix, H.2 needs new API calls and breaks the "no API spend" budget.

### H.2 — Add enrichment toggles to `_make_text`
- New constants `_ENRICH_VENUE`, `_ENRICH_TOPICS`, `_ENRICH_KEYWORDS` (default True).
- CLI flags `--enrich-venue/--no-enrich-venue`, etc., plus `--enrich-anchors-only`.
- Plumb through all four strategy functions.

### H.3 — Train two ablations
- **v3a**: strategy 3 fix only, no enrichment anywhere (closest to v2's text shape).
- **v3b**: strategy 3 fix + anchor-only enrichment (query keeps context, doc side stays clean).
- Identical hyperparameters to v3 (6 epochs, batch 32, max_seq 512, LR 2e-5). RTX 4070 Ti SUPER ≈ 1h each.

### H.4 — Decision rule
| Variant | Alone | + RRF |
|---|---|---|
| v2 | 0.5891 | 0.6643 |
| v3 | 0.5951 | 0.6590 |
| v3a | ? | ? |
| v3b | ? | ? |

Ship the variant with highest `+RRF` NDCG. If v3 still wins, the regression is within the 35-query eval's noise band → Phase M is the higher priority.

## Phase I — Strategy 3 coverage rebuild + persistent OpenAlex cache

### I.1 — Round-robin sampling in `run_strategy3` (`scripts/generate_sfu_training_data.py:585-725`)
- Replace the global `count >= max_total` early-exit with a per-provider quota: `target_per_provider = max_total // len(providers)` (≈36 with current defaults).
- Outer loop iterates **all** providers. Inner loop emits up to `target_per_provider` per provider.
- Replace `subjects[:4]` (line 659) with RNG-sampled `min(8, len(subjects))` per provider — alphabetical bias goes away.
- Replace `docs_for_pair[:2]` (line 681) with RNG-sampled `min(3, len(docs_for_pair))`.

### I.2 — Persistent OpenAlex paper cache
- New `scripts/openalex_cache.py` lifting the on-disk pattern already in `evaluate_sfu_queries.py:74-86, 102-163`. Generic `get_or_fetch(key, fetch_fn)`.
- Cache file: `data/openalex_works_cache.json` keyed by `f"subject::{name}"`, `f"citing::{work_id}"`.
- Reuse across strategies 1, 3, 4. No TTL — papers don't change. Manual delete on intentional refresh.

### I.3 — Stable per-(provider, subject) seed
Replace `random.Random(hash((provider, subject)))` (line 673) with sha1-based seed (Python's `hash()` is randomized per process unless `PYTHONHASHSEED` is set):

```python
import hashlib
seed_int = int(hashlib.sha1(f"{provider}::{subject}".encode()).hexdigest()[:8], 16)
sample_rng = random.Random(seed_int)
```

### I.4 — Cover unsubscribed SFU subjects

## Phase I-bis — Training data without OpenAlex (NEW — addresses user request)

OpenAlex enforces a 100k/day premium / 1k/day free quota and the local tracker hard-blocks at 900 (`config.py:69`, `openalex.py:243-260`). Below are four mutually-orthogonal sources that produce useful triplets with **zero or independent API budget**.

```ascii
   no-API ──────► A: Solr-only triplets (Solr cache already on disk)
                  │
   in-corpus ───► B: Re-mine the 8,724 cached papers (no new fetches)
                  │
   local-LLM ───► C: Ollama-served paraphrase / question generation
                  │
   independent ─► D: arXiv / Crossref / Semantic Scholar (separate quotas)
   API quotas       (S2 client already exists in src/lib/semantic_scholar.py)
```

### A. Solr-only triplets (zero API; ~3-6k triplets)
The `SFUDatabaseRegistry` exposes 766 records (`solr_cache.json`) with `name`, `subjects`, `provider`, `publicNote`, `description`, `contentTypes`. New strategy `run_strategy5` in `generate_sfu_training_data.py`:
- **Anchor**: `_generate_queries_from_db_record(rec)` (already exists, line 445) — mined from name/subject/description.
- **Positive**: a *different* DB record sharing ≥1 subject with the anchor record (description+name as text).
- **Negative**: random DB record sharing zero subjects.
- Dedup by (anchor, positive_db_id). Expected yield: 766 records × 5 queries × ~5 valid positives ≈ 4-6k after filtering.
- Cost: 0 API calls. Solr cache already exists.

### B. Re-mining the existing corpus (zero API; ~5k extra triplets)
The 8,724 clean triplets contain ~17k unique paper texts. Build new triplets by:
- For each anchor in the existing dataset whose paper text we have, find the **k-nearest in-corpus papers by sentence-BERT cosine** as additional positives. Use the *current* fine-tuned model so similarity is calibrated to the SFU domain.
- Add synthetic queries for each cached paper via template substitution against its title/topic.
- Cost: 0 API calls. CPU-only, ~30 min once.

### C. LLM-generated synthetic queries (local Ollama or Claude API)
Two implementations, one CLI:
- **`scripts/generate_synthetic_queries.py`** (new). For each cached paper text in `data/sfu_training_triplets.clean.jsonl`, call an LLM with: *"Given this paper abstract, write 3 short search queries (5-12 words each) a student in `{subject}` would type to find it."* Cache responses in `data/synthetic_queries_cache.json`.
- Backend selection via `--llm {ollama,claude,openai}`:
  - **`ollama`**: Local Llama-3 8B / Qwen-2.5 7B via `http://localhost:11434/api/generate`. Zero external cost. Fastest path on the dev box. The repo already has `ollama-proxy.py`.
  - **`claude`**: Claude API (Haiku 4.5 — fast/cheap) for higher quality. Use prompt caching on the system prompt to amortize cost.
  - Cost scales with corpus, not with OpenAlex quota.
- Each generated query becomes an **anchor**, paired with the source paper as **positive**, and a different-subject paper from the corpus as **negative**. Expected yield: 8,724 papers × 3 queries ≈ 26k synthetic triplets.

### D. Independent paper sources (separate quotas)
- **Semantic Scholar**: `src/lib/semantic_scholar.py` already exists with `search_papers`. Free tier: 100 req / 5 min unauthenticated. Add a `--source s2` flag to strategy 1; same citation-pair logic as OpenAlex but mining S2's citation graph. Quota independent of OpenAlex.
- **arXiv API**: `http://export.arxiv.org/api/query` — no rate limit beyond polite use, no key, no daily cap. Subject-aligned: arXiv categories (cs.LG, math.PR, ...) map cleanly to SFU's STEM subjects. New `scripts/arxiv_fetcher.py` analogous to `fetch_works_for_subject`.
- **Crossref REST**: `https://api.crossref.org/works` — polite pool 50 req/s with mailto. Already `lib/openalex.py:fetch_crossref_work` exists for single-DOI; extend to subject queries.
- All three populate the same `data/openalex_works_cache.json` (rename to `data/papers_cache.json` to reflect multi-source).

### Strategy yields summary

| Source | Triplets / run | API cost | New code |
|---|---|---|---|
| Strategy 5 (Solr-only) | 4-6k | 0 | `run_strategy5` |
| In-corpus re-mining | ~5k | 0 | `scripts/remine_corpus.py` |
| LLM synthetic (Ollama) | ~26k | 0 | `scripts/generate_synthetic_queries.py` |
| LLM synthetic (Claude) | ~26k | ~$5 with prompt caching | same script, `--llm claude` |
| arXiv | 5-10k | 0 | `scripts/arxiv_fetcher.py` |
| S2 citation graph | 3-8k | 0 (separate quota) | `run_strategy1 --source s2` |

### Acceptance for I-bis
- A successful `--strategy 5` run on the disk Solr cache produces ≥4,000 valid triplets covering ≥100 SFU subjects, with no network calls.
- LLM synthetic generation produces ≥3 queries for ≥80% of cached papers (some will refuse / produce gibberish — that's fine).
- A combined run (`--strategy 1 2 3 4 5 --llm-synthetic --arxiv-citations`) without the OpenAlex live API produces ≥30k clean triplets.

## Phase K — BM25-mined hard negatives

Strategies 1 and 3 currently use *random* cross-subject negatives. Model never sees lexically-similar-but-topically-wrong papers (the canonical DPR/ANCE finding).

### K.1 — `scripts/mine_hard_negatives.py`
For each (anchor, positive, subject):
- Query OpenAlex (or S2 / arXiv if I-bis cache is built) with the anchor text, take top 20.
- Filter to papers whose primary subject ≠ anchor's AND that aren't the positive.
- Pick the highest-ranked such paper as the hard negative.
- Cache in `data/hard_negatives_cache.json` keyed by anchor sha1.
- Reuse the rate-limit/backoff pattern in `evaluate_sfu_queries.py:123-149`.

### K.2 — Two negatives per anchor
Strategies 1 and 3 emit (anchor, positive, random_neg) **and** (anchor, positive, hard_neg). Doubles those strategies' triplet counts. With MNRL already in use (`train_embedding_model.py:364`), the explicit hard negative becomes a labeled negative *plus* in-batch negatives.

### K.3 — Acceptance
Triplet-eval mean margin on `data/splits/test.jsonl` rises ≥+0.02 vs current best.

## Phase M — Eval methodology

35-query eval (`data/sfu_eval_queries.json`, 14 subjects) is too small for 1-2% deltas.

### M.1 — Expand to 100+ queries / 40+ subjects
Sources:
- Rephrased Solr DB descriptions (1 per top-50 DBs by subject diversity).
- SFU library research-guide / FAQ pages (publicly browseable).
- Real query logs once Phase G ships and logging is in place.

Each query gets `subject(s)`, `difficulty {easy,medium,hard}`, `notes`.

### M.2 — Add MRR@10 and Recall@10 to `evaluate_sfu_queries.py:179-186`
NDCG alone hides whether the relevant doc is at rank 1 vs rank 10. Report all three.

### M.3 — De-bias the relevance proxy
Current `log(citation_count + 1)` correlates with OpenAlex's BM25 `relevance_score`, which is why "BM25 wins by construction" (0.8058). Mixed proxy:
```
rel(p, q) = 0.5 * log(p.citations + 1) + 0.5 * cos(embed(p), embed(seed_paper_for_q))
```
where `seed_paper_for_q` is one human-picked paper per query (≈ 8 person-hours for 100 queries).

### M.4 — Single results file
Migrate from `results/sfu_eval_results.json` to append-only `results/sfu_eval_history.jsonl`:
```json
{"timestamp": ..., "model": ..., "fusion": ..., "ndcg10": ..., "mrr10": ..., "recall10": ..., "per_subject": {...}, "notes": ...}
```
New `scripts/eval_compare.py` pretty-prints any two runs side-by-side, including a paired-bootstrap 95% CI on the delta.

### M.5 — Statistical-significance gate
A positive Δ NDCG with 95% CI overlapping zero is **not** a ship signal.


**Winner: `sfu-academic-embed-v4-bge` + RRF at 0.6689 NDCG@10**, beating the previous best (v3+RRF 0.6590) by **+1.5%**.

Key subject improvements of v4-bge+RRF over v4-mini+RRF:
- History: 0.856 → 0.874
- Indigenous Studies: 0.562 → 0.610
- Criminology: 0.536 → 0.582
- Political Science: 0.537 → 0.571

**Notable cross-metric pattern:** v4-mini+RRF leads on MRR@10 (0.408 vs 0.389), meaning it more often places the most relevant result at rank 1, while v4-bge+RRF dominates on Recall@10 (0.433 vs 0.378), meaning it surfaces more relevant results across the top 10. BGE's retrieval pre-training adds breadth; MiniLM's general-purpose tuning is sharper at rank 1 for common queries. The NDCG@10 figure weights both — BGE wins overall.

**Confidence caveat:** The +1.5% delta on a 35-query eval is real but not yet statistically confirmed. Paired bootstrap on 35 samples produces wide CIs; Phase M is required before treating this as a ship signal for model swap in production.

## Phase M — Eval methodology (updated post-L)

The 35-query set is insufficient to call +1.5% with confidence. Phase M is now the **top priority** — it determines whether v4-bge enters production.

### M.1 — Expand to 100+ queries / 40+ subjects

Target: 120 queries across all 40+ SFU subjects, stratified by difficulty.

Sources (in priority order):
1. **Rephrased Solr DB descriptions** — 1–2 queries per top-60 DBs by subject diversity (≈80 queries, zero API, ~3h human time).
2. **SFU Library research guides and subject FAQs** — publicly browseable; extract question-shaped sentences per subject.
3. **Synthetic from v4-bge embeddings** — for the 9 subjects currently under-represented in the eval set, use the Phase I-bis C pipeline (Ollama query gen against cached papers) to produce candidate queries, then filter to ≥3 human-approved per subject.
4. **Real query logs** — once Phase G ships and logging is active; back-fill into the eval set over time.

Each query must record: `subject(s)`, `difficulty {easy,medium,hard}`, `source {human,synthetic}`, `notes`. Human-approved label is required for any synthetic query entering the eval set.

### M.2 — Add MRR@10 and Recall@10

Already tracked in Phase L (MRR@10 and Recall@10 computed above). Wire into `evaluate_sfu_queries.py:179-186` as first-class outputs so all future eval runs emit all three metrics.

Phase L already demonstrated why this matters: NDCG@10 alone would have hidden the rank-1 vs top-10 trade-off between v4-bge and v4-mini.

### M.3 — De-bias the relevance proxy

Current `log(citation_count + 1)` correlates with OpenAlex's own BM25 relevance score. For the expanded eval set, use a mixed proxy:

```
rel(p, q) = 0.5 * log(p.citations + 1)
           + 0.5 * cos(embed(p), embed(seed_paper_for_q))
```

where `seed_paper_for_q` is one human-picked canonical paper per query. Estimated effort: ~6–8 person-hours for 120 queries. The seed papers should be recorded in `data/sfu_eval_queries.json` under a `seed_doi` field so the proxy is reproducible.

### M.4 — Append-only results history

Migrate from `results/sfu_eval_results.json` (single-run overwrite) to `results/sfu_eval_history.jsonl`:

```json
{"timestamp": "...", "model": "v4-bge", "fusion": "rrf", "ndcg10": 0.6689, "mrr10": 0.389, "recall10": 0.433, "per_subject": {...}, "notes": "Phase L final"}
```

New `scripts/eval_compare.py` accepts two run IDs (or model names) and prints:
- Side-by-side NDCG@10 / MRR@10 / Recall@10
- Per-subject delta table (top 5 gains, top 5 regressions)
- Paired bootstrap 95% CI on the NDCG@10 delta

### M.5 — Statistical-significance gate

**Ship rule:** a model swap in production requires:
1. NDCG@10 Δ > 0 with 95% paired bootstrap CI *entirely above zero* on the 120-query eval set.
2. No subject regression > −0.05 on any subject with ≥5 eval queries.
3. MRR@10 not worse (acceptable trade-off: ≤ −0.01 if Recall@10 gain ≥ +0.04).

v4-bge+RRF's current 35-query result (+1.5% NDCG, +5.5pp Recall, −1.9pp MRR) is promising but does not yet satisfy rule 1. Run Phase M before deploying the model swap.

### M.6 — Phase M acceptance criteria

1. `data/sfu_eval_queries.json` has ≥120 queries across ≥40 subjects, with `seed_doi` populated for ≥80% of entries.
2. `evaluate_sfu_queries.py` emits `ndcg10`, `mrr10`, `recall10`, and appends to `results/sfu_eval_history.jsonl`.
3. `scripts/eval_compare.py v3-rrf v4-bge-rrf` prints Δ and 95% CI; CI for NDCG@10 excludes zero.
4. v4-bge+RRF satisfies all three ship rules above.

## Phase O — Post-M roadmap (conditional on M confirming v4-bge)

Assuming Phase M confirms v4-bge+RRF as the new production model, the following work unlocks.

### O.1 — Deploy v4-bge to production

Replace the model path in `config.py` / `.env` with `models/sfu-academic-embed-v4-bge`. No code changes — the model path is already parameterized. Roll out under `SFU_FEATURE_RERANK_ENABLED=true` + `SFU_FEATURE_RRF_ENABLED=true` (both already set in Phase G).

### O.2 — CrossEncoder Tier 1.5 reranker (Phase N carry-over)

With v4-bge as the dense retrieval backbone, a CrossEncoder re-scoring pass on the top-20 RRF candidates becomes viable:
- Model: `cross-encoder/ms-marco-MiniLM-L-6-v2` (~70ms / 20 docs on CPU; acceptable for MCP server).
- Wire into `_maybe_rerank` as a second pass: `rrf_top20 → crossencoder_top10 → format`.
- New feature flag `SFU_FEATURE_CROSSENCODER_ENABLED`.
- Expected gain: +3–5% NDCG@10 (literature baseline on BEIR); adds ~100ms latency.

Latency budget for the MCP server needs to be established before this ships (see Phase N deferred note).

### O.3 — Real query-log feedback loop

Once Phase G is live and logging is active:
- Capture `(query_text, clicked_result_doi, rank_at_click)` as implicit relevance signal.
- 500+ real queries → augment Phase M eval set (label as `source: real_log`).
- 2,000+ real queries → fine-tune a query-log adapted checkpoint (v5).

### O.4 — Subject gap analysis

Phase L per-subject results revealed persistent weak subjects (estimated from MRR patterns):
- Subjects under 0.50 NDCG on the current eval set should receive targeted synthetic-query generation (Phase I-bis C) and a dedicated strategy-5 pass with tighter subject filtering.
- Specific candidates based on Phase L subject improvements: any subject with NDCG@10 < 0.55 after Phase M expansion warrants investigation.
