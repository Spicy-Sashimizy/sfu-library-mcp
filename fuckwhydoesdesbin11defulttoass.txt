> if i mount the script to windows would that compermise the sandbox if i 
was running bypass permission in a claude code instance would it be directly

● Yes, running the script directly on Windows reduces sandboxing compared to Docker. Here's the difference:

  Docker Container (Sandboxed)

  - ✅ Isolated filesystem - can't access Windows files directly
  - ✅ Limited to container's network and tools
  - ✅ If script is compromised, attacker is trapped in container
  - ❌ More complex setup

  Windows Python Direct (Less Sandboxed)

  - ⚠️ Script runs with your Windows user permissions
  - ⚠️ Can access any files you have access to
  - ⚠️ Can execute other programs on your system
  - ⚠️ If script is compromised, attacker has your level of access
  - ✅ Simpler setup

  For Claude Code with Bypass Permissions

  If you give Claude Code "bypass permissions" while running the script on Windows, Claude could potentially:
  - Read/write files on your system through the MCP server
  - Execute commands (if the script had that capability - this one doesn't)
  - Access environment variables

  Mitigation

  The SFU Library MCP script itself only makes HTTP requests to the library API - it doesn't access files or execute commands. So the risk is mainly:
  1. Supply chain attack - if the script author added malicious code
  2. Dependency vulnerabilities - if requests/selenium have exploits

  Best practice: If security is critical, fix the Docker container (Option 2) so the script runs isolated. The script's functionality (HTTP requests to SFU Library) works exactly the same either way.
